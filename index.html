Job hunt

A job and contract search you run as a loop instead of a panic. Built as a skill for an AI coding assistant, with a local dashboard and nothing to sign up for: no server, and no subscription needed. It runs on free channels, and uses a paid source only where you already pay for one.

You bring your CV and fifteen minutes. It builds a profile, then each run sources roles across the places worth looking, scores every one of them against that profile, checks the links are still alive, and hands you a ranked shortlist with a plain-English verdict on each. You decide what to do with it. It never applies to anything on your behalf.

How a run works

  1. Once: the intake. Your assistant reads your CV, then asks what the CV cannot tell it. Where you can legally work. What you would turn down. Your floor. The numbers you can defend. It writes profile.md, which you can edit any time. This is the part that decides whether the search is any good.
  2. Weekly: the search. Say "refresh my jobs". It works down the sourcing map: employer career pages and ATS boards first, then talent and contract platforms, niche boards, then aggregators and your own job-alert emails. It scores each role 0 to 100, opens every posting to confirm it is still live, and writes runs/2026-08-27.json.
  3. You: decide. Drop the run file on the dashboard. Set a status per role as you go. Hit Apply pack on the ones you want. Review the scoreboard on Friday.

The apply pack

For each role you actually pick, before anything gets written, five hostile readers go at your résumé against that job description:

  • The six-second screen. A recruiter with ninety résumés reads your top third and nothing else. Does it pass?
  • The keyword filter. Every concrete term the posting names, marked present, present in different words, or absent. Only true things get added.
  • The hostile hiring manager. Every bullet asked "how?" and "by how much?" until one of them cannot answer.
  • The comparison. Against the likely pool for this job, what is genuinely rare on your résumé, and what is on everyone's.
  • The gap hunter. The employment gap, the short stint, the pivot, the missing credential. What they will ask, and whether you address it on the résumé, in the letter, or in the room.

It ends with a call, and skip this one is a real answer. Then you get a tailored résumé for that posting, built by reordering, rewording and cutting your real one, never by inventing anything. It arrives as a file in its own application folder, next to a change log that labels every edit MOVED, REWORDED or CUT. There is no ADDED label, and three one-line commands catch most of what would need one. For a PDF, drop the file on resume.html and print it.

And a cover letter brief, not a cover letter

You get the points to hit, in order, each with the evidence attached: the opening angle, what to address head-on, what to leave out, and which of the posting's own words are worth echoing. Everything a letter needs except the sentences.

Those are yours to write. A letter in a voice that is not yours gets read back to you in the interview by someone who assumes you wrote it. Hand the brief to your own writing tooling if you have some, or spend the fifteen minutes. The hard part was the thinking, and the brief has already done it.

Setup

Two minutes for the skill, then fifteen for the intake.

1. Install the skill

Clone it straight into your assistant's skills directory. For Claude Code that is:

# macOS / Linux
mkdir -p ~/.claude/skills
git clone https://github.com/WorkflowtechAI/job-hunt.git ~/.claude/skills/job-hunt

# Windows PowerShell
New-Item -ItemType Directory -Force "$HOME\.claude\skills" | Out-Null
git clone https://github.com/WorkflowtechAI/job-hunt.git "$HOME\.claude\skills\job-hunt"

git pull in that folder later picks up changes. No git: download the ZIP from GitHub and unpack it so that ~/.claude/skills/job-hunt/SKILL.md exists. Watch that step, because unpacking one level off is the one install mistake that fails silently.

Restart the session, ask "what skills do you have?", and you should see job-hunt listed. Other assistants that read a skills or instructions folder work the same way; point yours at SKILL.md.

2. Make your folder

mkdir -p ~/job-hunt/runs ~/job-hunt/resume ~/job-hunt/applications
cp ~/.claude/skills/job-hunt/{dashboard,resume}.html ~/job-hunt/

Anywhere works, that is just the default. A private git repo is a good home for it: your whole search, versioned, and portable to a new machine.

3. Run the intake

Point your assistant at your CV and say "run the job-hunt intake". Answer the questions. It writes ~/job-hunt/profile.md and ~/job-hunt/resume/master.md at the end, both plain markdown you can edit whenever anything changes. A .docx is fine; it gets read, not retyped.

4. First search

Say "refresh my jobs". Expect it to take a while: the sourcing is wide and every posting gets opened and checked. Then open the dashboard and drop the run file on it.

Where the person you are working with matters

The intake asks two uncomfortable questions on purpose: your real salary floor, and an honest account of what you have actually shipped. Both are load-bearing. A profile that is polite about them produces a search that wastes your week.

What it will not do

  • It never applies for you. A run produces a shortlist and stops. You click every apply link and you send every message. This is not a limitation to be worked around; it is the design.
  • It never invents a claim. No borrowed projects, no rounded-up numbers, no credential-in-progress described as held. Everything in a letter has to survive the interview it gets you.
  • It never ships your data anywhere of its own. The profile, the CV, the runs and the pipeline are files in your folder, and the dashboard uses your browser's local storage with no network code in it at all. Your assistant still sends what it reads to its model provider, so install this into one you would trust with a résumé.
  • It never sends you to a job you have to pay to read. Boards that charge job seekers to view or apply get traced back to the employer's own posting, or dropped.
  • It never quietly bins a role. A posting it could not confirm shows up labeled unconfirmed rather than disappearing, because you can judge a flagged role and you cannot judge one you never saw.

The honest part

This is a search that works, not a machine that gets you hired. A good run surfaces two or three roles genuinely worth an application, and a thin week surfaces none. It will tell you that instead of padding the list, which is the whole reason the list stays worth reading.

The work you still have to do: the interviews, the follow-ups, the decisions, and the read-through on every tailored résumé before it goes out. What you get back is the sourcing, the ranking, the paperwork, and a process that does not fall apart in week three.
